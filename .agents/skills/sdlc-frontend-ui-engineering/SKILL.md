# SDLC Frontend UI Engineering

## Overview

Build production-quality user interfaces that are accessible, performant, and visually polished in React and React Native. The goal is UI that looks like it was built by a design-aware engineer at a top company — not like it was generated by an AI. This means real design system adherence, proper accessibility, thoughtful interaction patterns, and no generic "AI aesthetic."

## When to Use

- Building new UI components or screens (React Web / React Native)
- Modifying existing user-facing interfaces
- Implementing responsive layouts
- Adding interactivity or state management
- Fixing visual or UX issues

## Component Architecture

### File Structure

Colocate everything related to a component:

```
src/components/
  TaskList/
    TaskList.jsx          # Component implementation
    TaskList.test.jsx     # Tests
    TaskList.stories.jsx  # Storybook stories (if using)
    use-task-list.js      # Custom hook (if complex state)
```

### Component Patterns

**Prefer composition over configuration:**

```jsx
// Good: Composable
<Card>
  <CardHeader>
    <CardTitle>Tasks</CardTitle>
  </CardHeader>
  <CardBody>
    <TaskList tasks={tasks} />
  </CardBody>
</Card>

// Avoid: Over-configured
<Card
  title="Tasks"
  headerVariant="large"
  bodyPadding="md"
  content={<TaskList tasks={tasks} />}
/>
```

**Keep components focused:**

```jsx
// Good: Does one thing (React Native Example)
export function TaskItem({ task, onToggle, onDelete }) {
  return (
    <View style={styles.itemContainer}>
      <Checkbox checked={task.done} onChange={() => onToggle(task.id)} />
      <Text style={task.done ? styles.completedText : styles.text}>{task.title}</Text>
      <TouchableOpacity onPress={() => onDelete(task.id)}>
        <TrashIcon />
      </TouchableOpacity>
    </View>
  );
}
```

**Separate data fetching from presentation:**

```jsx
// Container: handles data
export function TaskListContainer() {
  const { tasks, isLoading, error } = useTasks();

  if (isLoading) return <TaskListSkeleton />;
  if (error) return <ErrorState message="Failed to load tasks" retry={refetch} />;
  if (tasks.length === 0) return <EmptyState message="No tasks yet" />;

  return <TaskList tasks={tasks} />;
}

// Presentation: handles rendering
export function TaskList({ tasks }) {
  return (
    <View style={styles.listContainer}>
      {tasks.map(task => <TaskItem key={task.id} task={task} onToggle={...} onDelete={...} />)}
    </View>
  );
}
```

## State Management

**Choose the simplest approach that works:**

```
Local state (useState)           → Component-specific UI state
Lifted state                     → Shared between 2-3 sibling components
Context                          → Theme, auth, locale (read-heavy, write-rare)
URL state / Navigation params    → Filters, shareable UI state, screen parameters
Server state (React Query, SWR)  → Remote data with caching
Global store (Zustand, Redux)    → Complex client state shared app-wide
```

**Avoid prop drilling deeper than 3 levels.** If you're passing props through components that don't use them, introduce context or restructure the component tree.

## Design System Adherence

### Avoid the AI Aesthetic

AI-generated UI has recognizable patterns. Avoid all of them:

| AI Default | Why It Is a Problem | Production Quality |
|---|---|---|
| Purple/indigo everything | Models default to visually "safe" palettes, making every app look identical | Use the project's actual color palette |
| Excessive gradients | Gradients add visual noise and clash with most design systems | Flat or subtle gradients matching the design system |
| Rounded everything | Maximum rounding signals "friendly" but ignores the hierarchy of corner radii | Consistent border-radius from the design system |
| Generic hero sections | Template-driven layout with no connection to the actual content | Content-first layouts |
| Lorem ipsum-style copy | Placeholder text hides layout problems that real content reveals | Realistic placeholder content |
| Oversized padding everywhere | Equal generous padding destroys visual hierarchy and wastes screen space | Consistent spacing scale |

### Spacing and Layout

Use a consistent spacing scale. Don't invent values:

```js
// React Native StyleSheet
const styles = StyleSheet.create({
  // Use the scale (e.g., multiples of 4 or 8)
  container: {
    padding: 16,      /* Good */
    gap: 12,          /* Good */
  },
  badContainer: {
    padding: 13,      /* Bad: Not on any scale */
    marginTop: 23,    /* Bad: Not on any scale */
  }
});
```

### Color

- Use semantic color tokens: `theme.colors.primary`, `theme.colors.surface` — not raw hex values inside components.
- Ensure sufficient contrast (4.5:1 for normal text).

## Accessibility

Every component must meet standards.

### React Web Accessibility

```jsx
// Every interactive element must be keyboard accessible
<button onClick={handleClick}>Click me</button>        // ✓ Focusable by default
<div onClick={handleClick}>Click me</div>               // ✗ Not focusable

// Label interactive elements that lack visible text
<button aria-label="Close dialog"><XIcon /></button>
```

### React Native Accessibility

```jsx
// Use Accessibility Props
<TouchableOpacity
  accessible={true}
  accessibilityRole="button"
  accessibilityLabel="Close dialog"
  accessibilityHint="Closes the current modal and returns to the previous screen"
  onPress={onClose}
>
  <XIcon />
</TouchableOpacity>

// Screen reader announcements
<Text accessibilityLiveRegion="polite">
  {tasks.length} tasks completed
</Text>
```

### Meaningful Empty and Error States

```jsx
// Don't show blank screens
function TaskList({ tasks }) {
  if (tasks.length === 0) {
    return (
      <View style={styles.emptyState}>
        <TasksEmptyIcon style={styles.emptyIcon} />
        <Text style={styles.emptyTitle}>No tasks</Text>
        <Text style={styles.emptySubtitle}>Get started by creating a new task.</Text>
        <Button title="Create Task" onPress={onCreateTask} />
      </View>
    );
  }

  return <ScrollView>...</ScrollView>;
}
```

## Loading and Transitions

```jsx
// Optimistic updates for perceived speed (React Query example)
function useToggleTask() {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: toggleTask,
    onMutate: async (taskId) => {
      await queryClient.cancelQueries({ queryKey: ['tasks'] });
      const previous = queryClient.getQueryData(['tasks']);

      queryClient.setQueryData(['tasks'], (old) =>
        old.map(t => t.id === taskId ? { ...t, done: !t.done } : t)
      );

      return { previous };
    },
    onError: (_err, _taskId, context) => {
      queryClient.setQueryData(['tasks'], context?.previous);
    },
  });
}
```

## Common Rationalizations

| Rationalization | Reality |
|---|---|
| "Accessibility is a nice-to-have" | It's a legal requirement in many jurisdictions and an engineering quality standard. |
| "The design isn't final, so I'll skip styling" | Use the design system defaults. Unstyled UI creates a broken first impression for reviewers. |
| "This is just a prototype" | Prototypes become production code. Build the foundation right. |

## Red Flags

- Components with more than 200 lines (split them).
- Magic numbers for spacing and styling.
- Missing error states, loading states, or empty states.
- No accessibility labels on icon-only buttons.
- Using TypeScript annotations (This project uses pure JS only).

## Verification

After building UI:
- [ ] Component renders without console errors.
- [ ] UI is tested across different screen sizes / orientations.
- [ ] Loading, empty, error, and success states handled when applicable.
- [ ] Follows the project's design system (spacing, colors, typography).
- [ ] Buttons and interactive elements have appropriate accessibility labels and roles.
- [ ] Uses `.jsx` or `.js` extensions, not `.tsx` or `.ts`.
